Three layers

From the published model to readings on top

On top

usdm-overlay

Readings of what each attribute and class holds: data, data in a string or words, each with its evidence. Findings about the model, each with a test.

The overlay is one example. With the model as a knowledge graph, new layers can be added on top: other standards linked to it and queried together.

In the middle

usdm-rdf

The same model, represented as a knowledge graph: a global identifier for each of the 86 classes and 693 attributes, linked to NCIt. Study files in JSON can be read into the same graph.

At the base

USDM v4, as published by CDISC

The UML model, the same model as YAML, the terminology workbook (USDM_CT.xlsx) and the API specification. Study designs are exchanged as JSON files.

Sentences and written rules. A person has to read them.

Beyond USDM

The words are not a dead end

A knowledge graph can represent the entities and relationships from study design to data capture. Structuring what the words say in such a graph turns them into data, and that is where the link from an endpoint to its assessments can live.

Such a link is one of the further layers that slide 2 leaves room for.
