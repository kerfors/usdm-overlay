usdm-overlay

https://kerfors.github.io/usdm-overlay/

Terms for an overlay graph that classifies and comments on the CDISC USDM v4 model as rendered in RDF/OWL by usdm-rdf. The overlay only points at usdm-rdf IRIs; it never changes them. Every assertion carries an evidence tier, so model-stated facts stay apart from readings of the model.

Design elements in plain languageObjectives, endpoints, eligibility criteria and the schedule: what USDM holds as data, and what is still words. Design elements as slides (PDF)The same content as four slides, ready to present or send. Explore the overlayEvery class and attribute, filterable by role, with the evidence for each reading, and the findings.

Findings

Ready to raise (4)

The published artefacts contradict themselves, or leave undefined something they rely on. The pinned files alone show it, and the ask is to make the artefacts consistent.

  • Abstract-class attributes carry a subclass's C-code
  • Extension classes carry no definitions
  • Population-level summary: term and definition disagree
  • Procedure type is an uncoded classification

For discussion (17)

Depends on a modelling choice CDISC may have made on purpose, or on content of the published example files.

  • Biomedical concept property datatypes are uncontrolled names
  • Biomedical concept references are relative API paths
  • Code systems are named by free strings
  • Schedule conditions are strings, not Condition instances
  • Objectives, endpoints and criteria have no link to document sections
  • Section references are used only for amendment changes
  • Eligibility identifier identifies only together with the category
  • No link between Endpoint and what it requires
  • Intercurrent event strategy: fixed set, specified as text
  • NarrativeContent holds its text by reference
  • Narrative refers to model instances by markup in text
  • Syntax-template parameters resolve through markup
  • Amendment number: definition says numerals, an example uses a letter
  • Syntax-template parameters are rarely used
  • Template parameters are matched by name inside text
  • Timing values follow ISO 8601 by convention only
  • Timing labels are typed, not generated from the value
